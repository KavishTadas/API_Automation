## 2. Architecture overview

The project has two complementary test tiers:

1. **Newman business-rule tier.** `collections/auth/Employee_Auth_API.json` tests successful and unsuccessful authentication, then the Attendance collections and `collections/Leave_API.json` exercise their respective HCM workflows. `collections/auth/Login_Auth_UAT_API.json` retains the separate UAT login scenarios. `scripts/run-newman.js` enforces run order, carries the token forward, retries only transient transport/server failures, and produces HTML and Allure results.
2. **Python generic-contract tier.** `tests/global_contract/` applies reusable protocol and OpenAPI checks to every active operation, while `tests/auto_generated/` contains generated endpoint smoke and response-shape checks. The generated suite is disposable output and must be regenerated rather than edited.

`openapi/openapi.yaml` is the authoritative response contract for the active HCM scope. Before Newman sends a request, `scripts/run-newman.js` loads and compiles the required OpenAPI schemas with AJV, injects the bundle into Newman, and the collection scripts validate real response bodies against it. The Python `tests/global_contract/` suite independently loads the same OpenAPI document and uses it for operation discovery, documented status codes, content types, security requirements, and contract metadata.

`api-docs/API_File.json` is an inventory generated by `scripts/generate-api-file.js` from active collection requests and verified Bruno requests. Pending collections and `bruno/unverified-endpoints/` are excluded. `scripts/generate-generic-tests.py` consumes that JSON inventory and recreates `tests/auto_generated/`. Do not hand-edit `api-docs/API_File.json`, its CSV counterpart, or anything under `tests/auto_generated/`; fix the authoritative source or generator and regenerate.

## 3. Why things are the way they are

### Retained UAT Login Auth and retired Approvals coverage

Per team decision, the standalone UAT login coverage is retained as `collections/auth/Login_Auth_UAT_API.json`, with its data-driven cases in `test-data/auth/Login_Auth_UAT_API.csv`. It remains active while the development team resolves the pending dev/UAT authentication API consolidation; do not remove or merge it into `Employee_Auth_API.json` until that ownership decision is complete. Approvals coverage remains retired because no working replacement endpoint has been verified, so Approvals does not belong in the active inventory or generated suite unless a real endpoint and contract are supplied.

### Certificate pinning on the auth host

`dev_mcdp_be.omfysgroup.com` has a legitimate, CA-trusted certificate, but the underscore in its hostname is rejected by strict RFC 6125 hostname validation. `scripts/pinned_tls.py` and `scripts/pinned-tls-agent.js` therefore skip only the invalid hostname-string comparison for this fixed host, retain certificate-chain and validity verification, and require the exact leaf-certificate SHA-256 fingerprint. This is certificate pinning, not disabled TLS verification.

The current pinned leaf certificate is valid from **August 7, 2026 through February 21, 2027 (UTC)**. Requests will correctly fail closed if it rotates; update both helpers before rotation or expiry and rerun the pin regression tests.

### Nullable leave purpose

`purpose` remains required as a field but permits either a string or `null`. Live data showed a March 2026 batch of 25 LWP records with the same application date, single leave date, leave type, many employees, and consecutive `lr_no` values stepping by two. That pattern indicates bulk or administratively created entries, for which a missing purpose is legitimate. Individually submitted employee leave is still expected to contain a purpose.

### Two expected failures in global contract checks

Only the Employee Auth parameters of `test_404_for_unknown_route` and `test_content_type_negotiation` are marked non-strict `xfail`. Probes against `*.omfysgroup.com` showed apparent organization-wide WAF/gateway route-and-header allowlisting rather than application behavior. That infrastructure policy cannot be corrected in this test repository or at the application route level, so the checks remain visible as expected failures instead of being weakened or deleted.

### Quarantined sample endpoints

`GET /users/me` is not part of the authoritative HCM OpenAPI contract, and the FastAPI application in `main.py` is only a local sample. Their checks are retained under `tests/unverified_endpoints/` and `bruno/unverified-endpoints/` for traceability and possible future investigation, but are explicitly skipped/excluded from HCM inventory generation and CI. Quarantine preserves useful context without presenting unverified endpoints as supported HCM coverage.

### `BASE_URL` is retained for Bruno flows

`BASE_URL` and its Postman/Bruno form `baseUrl` point to `https://uat-mcdp-be.omfysgroup.com` and are still intentionally used by the retained Bruno auth request and quarantined profile-investigation request. They are distinct from `AUTH_BASE_URL` (`https://dev_mcdp_be.omfysgroup.com`) and `LEAVE_BASE_URL` (`https://devmcdphcmplatform.omfysgroup.com`), which select the active Newman/Python auth and leave targets; only the active auth host requires certificate pinning. Do not remove `BASE_URL` merely because it is not the primary suite's endpoint selector—check the retained Bruno flows first.
