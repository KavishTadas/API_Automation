Design patterns and implementation style
- Data-driven testing:
  - CSV files in test-data/ map to collection filenames.
  - Example: test-data/Login_API.csv feeds collections/Login_API.json.
- Ordered test execution:
  - scripts/run-newman.js forces Login_API.json before Leave_API.json so auth can run first.
- Shared test context:
  - authToken and other non-empty Newman environment values are carried forward between collection runs.
- Generated reports:
  - Per-collection HTML files are generated with htmlextra.
  - Allure raw results are generated under reports/allure-results.
  - A consolidated HTML index is generated under reports/html/index.html.
  - The consolidated index includes Newman collection results plus auto-generated pytest results when Allure JSON or JUnit XML is present.
- Generated API file:
  - scripts/generate-api-file.js reads collections/ and bruno/.
  - It skips .pending. collections and non-request Bruno environment files.
  - It writes api-docs/API_File.csv and api-docs/API_File.json.
  - It detects authToken producers/consumers and links dependent APIs to the login/token-producing API.
  - It includes example request and response payload fields, masking sensitive placeholders such as passwords and tokens.
  - It preserves existing API row order, refreshes matching rows, and appends newly discovered APIs.
  - It snapshots previous API_File CSV/JSON versions into api-docs/history/ for audit.
- Generated generic tests:
  - scripts/generate-generic-tests.py reads api-docs/API_File.json first, then falls back to CSV.
  - It writes tests/auto_generated/ pytest files, shared helpers, and fixtures.
  - Generated tests use httpx, API File method/endpoint/body/parameters, and optional bearer auth when authToken is required.
  - Rows with missing base URL/endpoint are marked skipped.
  - Negative/non-200 API rows are marked skipped because they do not document a valid 200 request.
- Contract-first reference:
  - openapi/openapi.yaml describes expected endpoint behavior and schemas.
- CI artifact publishing:
  - GitHub Actions uploads HTML, Allure results, and Allure HTML report artifacts.

7. Known Issues, TODOs, and Notes

Known issues and risks

| Issue | Impact | Recommendation |
|---|---|---|
| README.md still describes the original FastAPI template | New contributors may miss the actual API automation purpose | Rewrite README for the Newman/HCM automation suite |
| Project naming is inconsistent | package.json, pyproject.toml, and OpenAPI imply different projects | Standardize project name across metadata |
| Python dependencies are unpinned | Reproducibility risk | Pin or use a lock file |
| .env.example includes real-looking credentials | Secret exposure risk | Replace with placeholders and rotate if valid |
| local/staging/production environments all point to UAT URL | Environment separation is misleading | Replace with real environment URLs or rename files |
| Latest generated Allure report has failures | Current test suite is not green against observed UAT report | Investigate authToken carry-forward and Leave API JSON errors |
| monitoring/health-check.js runs every JSON collection, including pending files | Monitoring can execute unfinished/sample collections | Add same .pending. skip logic as run-newman.js |
| monitoring/health-check.js does not load environments/*.json or shared env vars | Variable-based collections may fail during monitoring | Pass env file and envVar overrides to Newman |
| Bruno endpoints differ from Postman/OpenAPI endpoints | Bruno collection may be stale or for a different API | Align Bruno with /auth/token and documented HCM endpoints |
| scripts/url-check.js probes the same URL twice | Diagnostic output adds little value | Make it probe distinct candidate URLs or remove duplicate |
| scripts/url-check.js defines unused TOKEN | Dead code | Remove or implement intended behavior |
| OpenAPI lint warnings exist | Contract quality issue | Add operation description fields |
| reports/allure-html-report is staged/generated | Generated output may pollute repo history | Decide whether to ignore/remove or intentionally publish |
| group.com-like staged file exists | Looks accidental and contains stash/log-style text | Review and remove from staging if accidental |
| Mojibake appears in several files | Readability issue | Normalize files to UTF-8 |
| GET /messages returns key "messages:" | Odd response shape | Keep if intentional, otherwise rename to "messages" and update tests |
| No production app deployment exists | Repository tests APIs but does not deploy a service | Document that CI produces reports/artifacts only |

8. File-Level Details

main.py
- Creates FastAPI app instance.
- Defines in-memory messages_list dictionary.
- Routes:
  - GET / returns {"message": "Hello"}.
  - GET /about returns {"message": "This is the about page."}.
  - POST /messages/{msg_name}/ creates MsgPayload with incremental id.
  - GET /messages returns {"messages:": messages_list}.

models.py
- Defines MsgPayload Pydantic model:
  - msg_id: Optional[int]
  - msg_name: str

tests/test_main.py
- Uses FastAPI TestClient fixture.
- Tests:
  - test_home_route
  - test_about_route

scripts/run-newman.js
- Loads dotenv.
- Reads ENV and resolves environments/{ENV}.json.
- Fails early if environment file does not exist.
- Discovers non-pending JSON collections in collections/.
- Forces Login_API.json and Leave_API.json run order.
- Builds sharedEnvVars from process env:
  - baseUrl
  - empCode
  - empPassword
  - leaveBaseUrl
- For each collection:
  - Loads matching test-data/{CollectionName}.csv if present.
  - Runs Newman with htmlextra, allure, and cli reporters.
  - Exports htmlextra report to reports/html/report-{CollectionName}-{timestamp}.html.
  - Exports Allure results to reports/allure-results.
  - Carries non-empty environment values to sharedEnvVars.
  - Records summary counts.
- Before running:
  - Snapshots previous Allure history.
  - Clears reports/html, reports/allure-results, and reports/allure-report.
  - Restores Allure history into new results.
- After running:
  - Prints console summary.
  - Generates consolidated HTML index.
  - Exits 1 when any collection has assertion failures or Newman run errors.

scripts/generate-html-index.js
- Exports generateIndex(results).
- Can be run directly with node scripts/generate-html-index.js.
- Builds a dark themed unified HTML report with:
  - Overall status.
  - Collection count.
  - Newman request count.
  - Auto-generated pytest test count.
  - Passed, failed, and skipped counts.
  - Pass rate.
  - Newman duration.
  - Links to per-collection reports.
- Reads auto-generated pytest result files from:
  - reports/allure-results/generated-tests/**/*-result.json.
  - reports/allure-results/**/*-result.json when generated-tests is absent and entries match tests/auto_generated.
  - reports/**/*.xml JUnit files as a fallback when no Allure JSON is found.
- Maps auto-generated pytest result names back to tests/auto_generated/test_*.py API metadata.
- Adds an Auto-generated Test Cases section with API name, test case, status, duration, source, and details.

scripts/reporter-config.js
- htmlextra configuration:
  - darkTheme: true.
  - showOnlyFails: false.
  - skipSensitiveData: true.
  - omitRequestBodies: false.
  - omitResponseBodies: false.
  - showEnvironmentData: true.
  - timezone: Asia/Kolkata.

scripts/generate-api-file.js
- Dependency-free Node.js documentation generator.
- Reads Postman .json collection files from collections/ recursively.
- Skips .pending. collection files.
- Handles nested Postman folders and request items.
- Reads Bruno .bru HTTP request files from bruno/ recursively.
- Skips Bruno files that do not contain HTTP request blocks, such as environment files.
- Extracts:
  - Sr. No.
  - Module Name.
  - Sub-Module Name.
  - Access.
  - Functional Purpose.
  - Base URL.
  - Endpoint / Path.
  - HTTP Method.
  - Request Parameters.
  - Request Body.
  - Example Request Payload.
  - Request Body Schema.
  - Response (example/200).
  - Example Response Payload.
  - Dependent APIs / Services.
  - Owner / Developer.
  - API Identifier.
  - Comments.
- Creates api-docs/ when missing.
- Writes api-docs/API_File.csv and api-docs/API_File.json.
- Maintains api-docs/history/API_File_history.json plus timestamped previous CSV/JSON snapshots.
- Computes stable API identifiers from method, base URL, endpoint, module, and sub-module.
- Refreshes existing API rows in place and appends newly discovered API rows to the end of the API file.
- Automatically detects produced and consumed variables such as authToken, then links consumers to the producing login/token API.
- Masks sensitive values in example request payloads, including password, token, secret, API key, and authorization placeholders.
- Infers basic response examples from saved Postman responses or test-script assertions when no saved response is present.
- Uses git log for file owner/developer when available, with a direct Git HEAD author fallback when child process execution is restricted.

scripts/generate-generic-tests.py
- Reads api-docs/API_File.json when present.
- Falls back to api-docs/API_File.csv when JSON is absent.
- Creates tests/auto_generated/.
- Generates one pytest module per API row.
- Generates shared helper and fixture files:
  - tests/auto_generated/_api_test_helpers.py
  - tests/auto_generated/conftest.py
  - tests/auto_generated/__init__.py
- Each generated endpoint test file includes:
  - Status-code test expecting HTTP 200 for a valid request.
  - Response-schema test that validates against a JSON response example/schema when API_File provides one.
- Uses httpx.Client for requests.
- Resolves {{variable}} templates from:
  - OS environment variables.
  - .env.
  - environments/{ENV}.json or environments/{API_TEST_ENV}.json, defaulting to uat.
  - First CSV row from the data file referenced in API_File comments.
- Adds bearer Authorization header when API_File indicates authToken dependency.
- Skips private API calls when no AUTH_TOKEN, API_AUTH_TOKEN, or authToken is available.
- Skips generated tests for rows with missing base URL or endpoint.
- Marks non-200/negative API rows skipped because they do not represent valid-request checks.
- The script overwrites existing generated files and tolerates Windows PermissionError during cleanup.

monitoring/health-check.js
- Discovers JSON collections in collections/.
- Runs each with Newman CLI reporter.
- Converts Newman failures into structured log entries.
- Appends failures to monitoring/logs/health-YYYY-MM-DD.json.
- Marks collection degraded if any response time exceeds 2000 ms.
- Prints summary:
  - HEALTHY count.
  - DEGRADED count.
  - FAILED count.
